## 1. System Overview & Context

This repository bridges **JW Library** personal study user data with the **Watchtower Online Library ([wol.jw.org](https://wol.jw.org))**.

### Key Concept
JW Library export files (`.jwlibrary`) do **not** contain publication text. Instead, they store highlights as lightweight relational records in an embedded SQLite database (`userData.db`). A highlight is an abstract tuple:
- **Location**: publication document ID or Bible book & chapter.
- **Word Range**: 0-based token offsets within a specific paragraph or verse.
- **Style**: Color index (1 to 6).

The **WOL Highlights** extension (`wol-highlights/`) runs entirely client-side in Firefox (Manifest V3), parses the backup archive using WebAssembly SQLite (`sql.js`), extracts and indexes highlights into `chrome.storage.local`, and dynamically paints matching text on `wol.jw.org` using an accurate Unicode tokenization and DOM TreeWalker alignment engine.

## 3. Data Model & SQLite Schema

Highlights are queried using the following relational structure from `userData.db` (Schema Version 16):

```sql
SELECT
  l.DocumentId AS documentId,
  l.BookNumber AS bookNumber,
  l.ChapterNumber AS chapterNumber,
  l.KeySymbol AS keySymbol,
  l.MepsLanguage AS mepsLanguage,
  b.BlockType AS blockType,
  b.Identifier AS identifier,
  b.StartToken AS startToken,
  b.EndToken AS endToken,
  u.ColorIndex AS colorIndex
FROM UserMark u
JOIN Location l ON l.LocationId = u.LocationId
JOIN BlockRange b ON b.UserMarkId = u.UserMarkId
WHERE l.Type = 0
  AND b.StartToken IS NOT NULL
  AND b.EndToken IS NOT NULL;
```

### Table Roles
- **`Location`**:
  - `Type = 0`: Standard publication document or Bible chapter (used by all highlights).
  - `DocumentId`: Unique MEPS document identifier for periodicals, books, and workbooks (e.g., `2025441`). Maps directly to WOL URLs: `/wol/d/r<region>/lp-<lang>/<DocumentId>`.
  - `BookNumber` & `ChapterNumber`: Used for Bible chapters (where `DocumentId` is `NULL`). Book 1 = Genesis, 2 = Exodus, etc.
  - `KeySymbol`: Publication code (e.g. `w` for Watchtower, `nwtsty` for Study Bible).
  - `MepsLanguage`: Numeric language ID (0 = English `E`, 1 = Spanish `S`).
- **`UserMark`**:
  - `ColorIndex`: Highlight color (1: Yellow, 2: Green, 3: Blue, 4: Red, 5: Orange, 6: Purple).
  - `UserMarkGuid`: UUID for cloud sync across devices.
  - `StyleIndex`: Always 0 (standard background highlight).
  - `Version`: Token layout version (always 1).
- **`BlockRange`**:
  - `BlockType`: `1` = Article paragraph; `2` = Bible verse.
  - `Identifier`: Paragraph number (`data-pid` in WOL DOM) or Bible verse number. Note: Study article paragraphs in WOL start at `data-pid="2"` because `data-pid="1"` is the article title.
  - `StartToken` & `EndToken`: Inclusive 0-based token index range (`[StartToken, EndToken]`).
  - *Multi-range highlights*: When a highlight spans multiple paragraphs or verses, JW Library creates multiple `BlockRange` rows linked to the same `UserMarkId`.

## 4. Tokenization Engine Specification (`lib/tokenize.js`)

JW Library addresses words and punctuation using a strict token stream. Any modification to `tokenize.js` must adhere to these rules:

1. **Word Tokens**:
   Regex pattern: `WORD = /[\p{L}\p{N}\p{Pc}]/u`
   Matches Unicode letters (including accents like `á`, `ñ`), numbers, and connector punctuation (`_`). Sequences of consecutive word characters form **one token**.
2. **Punctuation Tokens**:
   Every non-whitespace character that does not match `WORD` is an **individual token** (e.g. `.`, `,`, `“`, `”`, `(`, `)`, `-`).
3. **Whitespace is Skipped**:
   Characters matching `SPACE = /[\s\u00A0\u1680\u2000-\u200A\u2028\u2029\u202F\u205F\u3000\uFEFF]/u` are skipped and never count as tokens.
4. **Special Tokens**:
   Soft hyphens (`\u00AD`) and zero-width spaces are each treated as individual tokens.

## 5. WOL DOM Architecture & Highlight Placement (`lib/highlight.js`)

### DOM Element Targets on `wol.jw.org`
- **Articles**: Container is `#article`. Target paragraphs are `p[data-pid="<Identifier>"]`.
- **Bible Verses**: Container is `#article`. Target verses are `span.v[id^="v<book>-<chapter>-<verse>-"]`. A verse may consist of multiple adjacent `span.v` fragments (e.g. if broken by poetry formatting or section headers).

### Elements That Must Be Ignored During Text Collection
When traversing text nodes in a block, the DOM `TreeWalker` **must reject** text inside:
- Paragraph numbers: `.parNum`
- Page numbers: `.pageNum`
- Footnote links/markers: `.fn`
- Verse / chapter anchors: `a.vl`, `a.cl`
- Ruby annotations: `rt`, `rp`
- Existing highlights: `mark.wol-hl`
- Study Bible cross-reference indicators: `a.b` where text content is strictly `"+"`

### Slicing & Wrapping Algorithm
1. `collectText(roots)` extracts concatenated text and records `[stringStart, stringEnd]` for every valid text node.
2. `tokenize(text)` produces token boundary offsets `[{ start, end }]`.
3. `slicesFor(tokens, parts, startToken, endToken)` maps the token range to character slices on specific DOM `Text` nodes.
4. Slices are sorted in **descending document order** (`documentOrderDescending`).
5. `wrapSlice(node, start, end, color)` uses `node.splitText()` to isolate the target slice and wraps it with `<mark class="wol-hl wol-c<color>">`. Descending order ensures earlier node offsets are never invalidated by subsequent splits.
6. When clearing marks (`clearMarks`), all `<mark.wol-hl>` elements are unwrapped and parent nodes are cleaned up with `parent.normalize()`.

## 6. WebExtension Implementation Rules & Constraints

### Firefox Content Script Scripting
- In Firefox (MV3), content scripts **cannot** use ES module syntax (`import`/`export`).
- Scripts in `manifest.json` are loaded as standard sequential scripts:
  1. `lib/tokenize.js`
  2. `lib/languages.js`
  3. `lib/highlight.js`
  4. `content.js`
- Functions declared in earlier scripts are globally accessible in later scripts. **Do not add `export` or `import` statements to content scripts.**

### Extension Security Policy (CSP)
- `manifest.json` defines:
  ```json
  "content_security_policy": {
    "extension_pages": "script-src 'self' 'wasm-unsafe-eval'; object-src 'self'"
  }
  ```
  `wasm-unsafe-eval` is required for `sql.js` WebAssembly execution inside the popup.

### Backup Parsing (`lib/backup.js`)
- Supports `.jwlibrary` (Zip) and uncompressed SQLite files.
- Uses `DecompressionStream("deflate-raw")` to stream and decompress `userData.db` directly in memory without third-party zip libraries.
- Index format stored in `chrome.storage.local["wolMarks"]`:
  ```typescript
  interface StoredIndex {
    version: 1;
    highlightCount: number;
    ignored: number;
    documentCount: number;
    bibleChapterCount: number;
    colorCounts: Record<number, number>;
    fileName?: string;
    loadedAt?: string;
    enabled?: boolean;
    docs: Record<string, Record<string, [startToken: number, endToken: number, colorIndex: number][]>>;
    bible: Record<string, Record<string, [startToken: number, endToken: number, colorIndex: number][]>>;
  }
  ```

### Reactive Page Monitoring (`content.js`)
- `content.js` attaches a `MutationObserver` to `document.documentElement` to detect client-side page transitions on `wol.jw.org`.
- Mutations trigger `schedule()` with a 200ms debounce.
- Status is communicated via messages `{ type: "wol-status" }` and `{ type: "wol-reapply" }`.
- Live status indicator: `document.documentElement.dataset.wolHighlights = "empty" | "on" | "off" | "error:..."`.

## 7. Verification & Testing

### Running In-Browser Tests
The test runner is located at `wol-highlights/test/run.html`. It tests:
1. Parsing parity between uncompressed `userData.db` and zipped `userdata.zip`.
2. Exact highlight count matching (2,765 highlights in reference dataset).
3. Document 2025441 (Watchtower June 2025, Jacob's last words part 2):
   - 69 highlights placed, 0 skipped.
   - Paragraph 7 word spans (tokens 53–62 and 74–88).
   - Paragraph 10 sentence match.
4. Bible chapters (Exodus 5:9, Exodus 6:3, Exodus 6:6) ensuring verse numbers are excluded and boundary punctuation matches expected offsets.

### Packaging & Development Execution
- **Rebuild Extension Package**:
  ```bash
  ./build.sh
  ```
  Zips `wol-highlights/` into `wol-highlights.xpi` excluding tests.
- **Run Firefox with Extension Pre-Loaded**:
  ```bash
  ./run-firefox.sh
  ```
  Launches a clean temporary Firefox profile, injects the extension via Marionette WebDriver, and navigates to `https://wol.jw.org`.

### Developer Checklist for Code Changes
- [ ] If changing tokenization: verify punctuation boundaries and non-breaking space handling against test fixtures.
- [ ] If changing DOM wrapping: ensure `clearMarks()` properly restores the DOM and `parent.normalize()` is called.
- [ ] Ensure no `import`/`export` syntax is introduced into content scripts (`lib/tokenize.js`, `lib/languages.js`, `lib/highlight.js`, `content.js`).
- [ ] Ensure all operations remain 100% offline and no external network calls are introduced.
- [ ] Run `./build.sh` to update `wol-highlights.xpi` before deployment or release.
